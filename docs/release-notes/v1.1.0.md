# v1.1.0

Agent-loop, provider, and file-structure refresh. No new database tables or
column drops; `schema_version` unchanged. `deploy/release-policy.json` stays
`backward-compatible` / `recent:2`.

## Upgrade notes

- **Prompt manifest v6.** Existing `managed`-mode profiles built from a v4/v5
  template fingerprint are recognized automatically via
  `prompts/legacy_defaults.json` and show `migration_required` in the
  settings page; apply the one-click migration there. Persona text and
  additional instructions are preserved — only the shared rule sections are
  replaced. Profiles already on a fully custom (`legacy`) prompt are left
  alone; nothing is guessed or auto-split.
- **Tool allowlists.** Old tool names in a saved `enabled_tools` allowlist are
  remapped to the current catalog (`migrate_tool_names`) the first time a
  profile is read. Nothing needs to be re-saved by hand, but a profile with
  an explicit allowlist does not automatically gain newly added tools —
  enable those from the forum/web tool settings if wanted.
- **Config.** New `.env` / `deployment.toml` keys (`model_call_timeout`,
  `image_concurrency`, the retuned `no_progress_batches` / `query_limit` /
  `model_limit` / `final_reserve_seconds` defaults) all ship with defaults.
  The production `/opt/shuiyuan/shared/deployment.toml` does not need any
  manual edits to pick up this release.
- **SimpleMCP image.** The MCP tool server image is rebuilt because tool
  return shapes changed (`image_inputs`, `web_read`/`web_search` payloads).
  This does not touch the database image; both roll independently per
  `deploy/compose.yaml`.
- **Removed providers.** OpenRouter, MiMo, and Tongyi/DashScope chat-provider
  code is deleted. Any stored model config or profile still pointing at one
  of those providers falls back to the default DeepSeek endpoint on next
  read — there is no automatic credential migration because there is nothing
  to migrate (DeepSeek used its own key already).

## Provider and agent loop

- DeepSeek is now the only chat provider (Responses API and Chat Completions
  both stay supported, selected by `DEEPSEEK_MENTION_API_FORMAT`), plus the
  existing `gpt-image-2`-based image generation endpoint. All OpenRouter/
  MiMo/Tongyi code paths, config fields, and their dedicated tests are gone.
- Context projection now drops whole stale tool-call/result rounds instead
  of rewriting kept message content, so the prompt prefix stays byte-stable
  turn over turn and DeepSeek's disk-based prefix cache keeps hitting.
- A three-layer time budget bounds every individual model call
  (`model_call_timeout`, default 180s) in addition to the per-turn deadline
  and the final-answer reserve, instead of only the outer timeout.
- Retrieval control defaults were retuned (`no_progress_batches=2`,
  `query_limit=30`, `model_limit=14`, `final_reserve_seconds=150`) based on
  observed convergence behavior; see `docs/agent-tools.md` for the current
  table.
- Forum reads (topic details, user lookups, search) get a short in-process
  TTL cache to cut redundant HTTP calls within and across nearby turns.
- Reply and image-generation concurrency are both configurable via
  `[common.runtime]` (`image_concurrency`, default 2) instead of being
  implicitly serialized.

## Tools and vision

- Tool schemas and docstrings were rewritten to a consistent Chinese
  three-part format (when to use / parameter notes / return shape); error
  envelopes are uniformly `status/code/message/retryable` with a `hint` on
  common failures.
- `web_read` produces lighter Markdown with less boilerplate, returns page
  `title`/`published_at` when declared, and rejects Shuiyuan URLs with a
  pointer to `forum_read` instead of trying to fetch them unauthenticated.
- `forum_read` short-URL derivation now computes `upload://<base62(sha1)>`
  from `secure-uploads`/`optimized` paths, fixing 403s on image downloads
  that require a signed direct URL the bot never had.
- Images stay metadata-only by default; the model must ask for `images=auto`
  (or `images=selected` with `image_refs` for `forum_read`) to load them.
  Small images (≤512px, ≤300KB) go inline at low detail; the rest go through
  the Files API with a 7-day cache.
- Repeated `users(username=…)` calls in the same batch are merged into one
  lookup and split back out by call id.

## Frontend

- Light/dark theming is a real CSS custom-property system now (previously
  partial/inconsistent), including chat bubbles, forms, and modals.
- BBCode (`[details]`, `[grid]`, `[quote]`, `[img]`, `[url]`, `[spoiler]`) is
  preprocessed to HTML before Markdown rendering, so forum-sourced content
  in the chat view renders instead of showing raw tags.
- The run/execution-round view surfaces tool calls, retrieval progress, and
  failures more directly instead of only a final text bubble.

## File structure

- `interfaces/api/app.py` (was ~1370 lines) is now just `create_app()` and
  middleware wiring; routes live under `interfaces/api/routes/` by concern,
  shared helpers in `interfaces/api/support.py`.
- `features/mention/mention_chat_model.py` (was ~2290 lines) keeps class
  lifecycle, graph assembly, and the model-invocation node; context loading,
  MCP/tool adapters, and response finalization moved to `context.py`,
  `tools_runtime.py`, and `finalize.py` as mixins composed onto
  `MentionChatModel`. `MentionGraphState` moved to `graph_state.py`.
- `test_architecture_boundaries.py` gained a `features/` must not import
  `interfaces/` rule.
- `shuiyuan/` and `database/` stay as legacy flat packages behind the
  existing `infrastructure/forum/` adapter layer rather than being merged
  into `infrastructure/` wholesale — the boundary they need
  (`application`/`domain` never import them directly) was already enforced
  and correct, and moving ~2500 lines of live forum-client/DB-manager code
  for a purely cosmetic reorganization was judged not worth the risk in this
  release. Still discouraged from growing further in place.
